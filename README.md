# CeZeOs

[![MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Открытый прототип социальной сети CeZeOs. Web/PWA для публикаций, сообществ и независимых Регионов. Для запуска нужен Node.js 24 или новее. Зависимости npm не требуются.

```powershell
cd cezeos
node server.mjs
```

Откройте <http://127.0.0.1:4173/>. При первом открытии появится экран регистрации. Через «Смотреть ленту» можно перейти к публичным записям, через «Деморежим» — создать локальный профиль. При локальном запуске приложение по умолчанию слушает только loopback. Порт можно изменить переменной `CEZEOS_PORT`.

## Возможности

- Лента с четырьмя режимами и фильтрами, отдельные обсуждения и личные закладки. Поиск по людям, сообществам и записям.
- Публикации, фото, аудио, видео и статьи. Атрибуция вручную, реакции, комментарии, редактирование, закрепление и ссылки.
- Профили, заявки в друзья, подписки, четыре уровня видимости записей. Открытые и закрытые сообщества с заявками на вступление.
- Wiki с категориями, историей и восстановлением текста через новую ревизию.
- Устанавливаемая оболочка PWA на совместимом браузере. Данные и вложения хранятся в `data/cezeos.sqlite` и не помещаются в офлайн-кэш.

Демопрофиль привязан к одной браузерной сессии. После выхода повторный вход в тот же профиль в этой версии недоступен. Медиа ограничены 24 МиБ на файл и хранятся в SQLite. Стартовое фото и звуковая зарисовка созданы для демонстрационных записей.

## Вход через Telegram

В настройках Login Widget в BotFather зарегистрируйте точный адрес перенаправления `<origin>/api/auth/telegram/callback` и оставьте подпись RS256. Перед запуском задайте в окружении `CEZEOS_TELEGRAM_CLIENT_ID`, `CEZEOS_TELEGRAM_CLIENT_SECRET` и `CEZEOS_PUBLIC_ORIGIN`. Последняя переменная содержит базовый адрес приложения без пути. При HTTPS передавайте исходный Host через локальный обратный прокси. Используйте адрес, который разрешает BotFather и который доступен в браузере. На указанном адресе станет доступна кнопка Telegram. Проверка использует OpenID Connect с PKCE, одноразовый запрос и проверку подписи токена.

Кнопку Aquamarine можно подключить после появления согласованного подтверждения для сторонних сайтов, которое связывает разовый запрос со стабильным ID аккаунта. Цвета и фирменное солнце взяты из темы CeZeOs в исходниках Aquamarine. [Сайт Aquamarine](https://aquamarinemessenger.pw/)

## Регионы и Docker на сервере

Для публичного сайта подготовлен [профиль cezeos.pw](deploy/cezeos.pw.md) с автоматическим HTTPS и перенаправлением `www`.

Каждый Регион запускается отдельно, со своей SQLite-базой и ключом Ed25519. Контейнер слушает порт 4173 и пишет данные в именованный том. Порт хоста по умолчанию доступен только локально. Для доступа с телефона или другого компьютера задайте `CEZEOS_PUBLIC_ORIGIN` и поставьте HTTPS-прокси, сохраняющий исходный заголовок Host. [Пример прокси](deploy/Caddyfile.example)

```bash
cp .env.example .env
docker compose -p cezeos up -d --build --wait
curl http://127.0.0.1:4173/healthz
```

Через `CEZEOS_HOST_PORT` задаётся внешний порт. Для нескольких Регионов используйте разное имя проекта Compose, разные порты и разные публичные адреса. Второй Регион может получить ID первого из `/.well-known/cezeos-region.json`. Сверьте ID с оператором первого Региона по доверенному каналу, затем добавьте его адрес и ID в массив `CEZEOS_PEERS`. Раздел «Регионы» показывает доступность и подписанные публичные записи. Текущий протокол передаёт текст и ссылку на оригинал. Права записи, репликация медиа и перенос аккаунта между Регионами пока отсутствуют. [Docker Compose](https://docs.docker.com/reference/compose-file/services/)

На Windows для разработки Docker не требуется. Для второго экземпляра задайте `CEZEOS_PORT`, `CEZEOS_PUBLIC_ORIGIN` и отдельный `CEZEOS_DATA_DIR` в другом окне PowerShell. Операторский запуск на Linux тоже может использовать Node.js 24 без Docker, если обновления и перезапуски выполняются отдельно.

### Обновления и резервные копии

Тег вида `v0.2.0` запускает CI-публикацию `linux/amd64` и `linux/arm64` в GHCR. После публикации укажите `CEZEOS_IMAGE` в `.env` и запустите `node update.mjs cezeos` на хосте. Скрипт скачивает образ, сохраняет снимок SQLite и ключ Региона в томе, проверяет новую версию через `/healthz` и при ошибке возвращает предыдущий образ. Он не заменяет базу автоматически. Для разрушающих миграций требуется отдельная процедура восстановления. Снимок содержит приватные данные и ключ, его нужно хранить в закрытом резервном хранилище.

Таймер и сервис systemd находятся в `deploy/`. Они рассчитаны на размещение проекта в `/opt/cezeos` и запуск от оператора, имеющего доступ к Docker. Автообновление запускается только после установки этих юнитов и включения таймера администратором.

### Общий Синклит и единый Триумвират

Включите `CEZEOS_GOVERNANCE_HOME=1` только на одном сервере. На остальных Регионах укажите его адрес и ID в `CEZEOS_PEERS`, а его ID также задайте в `CEZEOS_GOVERNANCE_REGION_ID`. Они показывают подписанный публичный состав и ведут на общий сервер для входа, заявок и голосования. Сессии CeZeOs пока привязаны к серверу. Тексты заявок и дел, права участников и голоса в публичный обмен не попадают.

Оператор вводит ники Aquamarine. Профили CeZeOs могут появиться позднее.

```bash
docker compose -p cezeos exec -T region node operator.mjs set-triumvirs @nick1 @nick2 @nick3
```

Без Docker выполните `node operator.mjs set-triumvirs @nick1 @nick2 @nick3` с `CEZEOS_GOVERNANCE_HOME=1` и тем же `CEZEOS_DATA_DIR`, что у общего сервера. Команда обновляет весь состав. Подтверждение оставшихся ников сохраняется. Роль активируется после подписанного подтверждения Aquamarine с указанным ником и закрепляется за стабильным ID этого аккаунта. Для уже привязанного аккаунта доступна кнопка «Обновить подтверждение Aquamarine».

На общем сервере участник подаёт заявку в разделе «Синклит», видит статус и может отозвать заявку до решения. Два совпадающих голоса принимают или отклоняют заявку. После приёма участник может вносить дела. Два совпадающих голоса триумвиров также закрывают дело. Голоса и решения журналируются. Состояние прежних региональных ролей не даёт полномочий в общем Синклите, старые записи сохраняются в базе.

### Связь с Aquamarine

Привязка включается после настройки HTTPS-адреса издателя Aquamarine и его публичного ключа Ed25519. На стороне CeZeOs подключённый аккаунт получает отметку в профиле. На стороне Aquamarine предусмотрена проверка подписанного подтверждения для отображения CeZeOs ID и открытия профиля. Сам клиент Aquamarine должен поддержать обмен. Региональные идентификаторы пока зависят от ключа Региона.

- `POST /api/ecosystem/aquamarine/start` выдаёт разовый запрос `challenge`, `issuer` и `audience` на 5 минут. Издатель Aquamarine после проверки своей сессии подписывает UTF-8 строку `aquamarine-cezeos-link-v1.<body>`. `body` — JSON в base64url с полями `iss`, `aud`, `sub` (стабильный идентификатор), `handle` (ник Aquamarine, обязателен для подтверждения роли триумвира), `purpose: "link"`, `challenge`, `exp` (миллисекунды Unix). Пользователь передаёт `<body>.<signature>` при завершении привязки.
- `POST /api/ecosystem/aquamarine/grant` принимает 32-байтовый запрос Aquamarine в base64url. Для привязанного участника он возвращает `<body>.<signature>`, подписанный ключом Региона по строке `cezeos-aquamarine-grant-v1.<body>`. Получатель закрепляет ключ Региона, проверяет `iss`, `aud`, `challenge`, `aquamarineSubject` и срок в 60 секунд. Подтверждение содержит региональный `sub`, публичный URL профиля и разрешения `cezeos.badge` и `cezeos.profile`. Проверенный запрос погашается однократно на стороне получателя.

### ПК, Android и iPhone

Один HTTPS-сайт работает на компьютере и телефоне. CeZeOs можно установить с сайта как PWA. На iPhone откройте его в Safari и добавьте на экран «Домой» с режимом веб-приложения. [Инструкция Apple](https://support.apple.com/en-az/guide/iphone/iphea86e5236/26/ios/26)

В `mobile/android/` находится проект Android Trusted Web Activity с пакетом `org.cezeos.app`. Для сборки нужны JDK 17, Android SDK 36 и Gradle 8.13. Укажите HTTPS-адрес Региона как `CEZEOS_APP_ORIGIN` и выполните `gradle -p mobile/android assembleDebug signingReport`, либо запустите workflow «Android preview» с адресом. APK для тестирования появится в `mobile/android/app/build/outputs/apk/debug/` или в артефактах запуска CI. Укажите SHA-256 сертификата используемой подписи в `CEZEOS_ANDROID_SHA256`. Сервер опубликует его на `/.well-known/assetlinks.json` для полноэкранного запуска. Тестовый ключ GitHub Actions пересоздаётся, для распространения нужен постоянный ключ. [Руководство по Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity/quick-start)

## Ограничения запросов

Изменяющие запросы: у вошедшего участника до 60 сразу, затем 1 в секунду; без входа — до 20 с адреса, затем 1 в 5 секунд. Чтение не ограничивается. Вложения: не больше двух одновременных загрузок на участника и четырёх на сервер; начало файла должно соответствовать заявленному формату. Лишний запрос получает `429` и `Retry-After`. Счётчики хранятся в памяти процесса.

Адрес без входа берётся из последней записи `X-Forwarded-For`, только если соединение пришло с этой машины или из частной сети (обратный прокси). Если порт сервера открыт в частную сеть напрямую, клиент из неё может подставить этот заголовок и обойти ограничение по адресу.
